# ForexSmartBot 3.4.6 Features

## Crypto wallet connect (first shippable slice)

Desktop PyQt cannot use browser `window.ethereum` injection. This release
ships a **WalletConnect URI + MetaMask deep-link** path for EVM and a
**Phantom Solana universal-link scaffold**, plus a chain registry and
Settings UI.

### Module: `forexsmartbot.wallet`

| Piece | Role |
| --- | --- |
| `chains` | Registry: major EVM + Solana clusters; **Robinhood Chain** `4663` / testnet `46630` (official docs) |
| `metamask` | Begin WC v2 URI + `https://metamask.app.link/wc?uri=…`; complete/attach **public** address |
| `phantom` | Build `https://phantom.com/ul/v1/connect?…` (Solana); EVM via extension documented as follow-on |
| `walletconnect` | Pairing URI builder; `WALLETCONNECT_PROJECT_ID`; phishing warning |
| `broadcast` | `make_broadcast_fn` / `wallet_address_for_dex` — align with 1inch dry-run + double opt-in |
| `manager` | Facade used by Settings → Wallet |

### Settings → Wallet

- Provider: MetaMask or Phantom
- Chain picker from registry
- Begin connect → shows WC URI / deeplink (copy / QR-ready text)
- Attach address (session) or Complete connect after wallet approve
- Disconnect clears RAM session; settings may keep **public address only**

### 1inch DEX alignment

- Connected EVM session address used as swap `from` when present
- Default remains **dry-run**; broadcast still needs `FSB_LIVE_TRADING=1` +
  `FSB_DEX_BROADCAST=1` + injected signer (wallet session ≠ private key)

### Opsec

- No private keys / seed phrases in app storage by default
- Seed-like input rejected; WC `symKey` process-RAM only
- Never force live broadcast

- `tests/test_wallet_connect.py` — mocked connectors, chains, broadcast guard
